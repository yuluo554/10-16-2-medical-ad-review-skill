- **版本**：v1（2026-10-15）
- **上游**：`plan/01-题目文档.md` §二（首期五个模块）、`plan/02-架构与技术选型.md`

## 一、判定语义总纲（最贵的一节，先定死）

### 1.1 结论状态词汇（四态，不是三态）

题面分级口径是 BLOCK / WARN / OK 三级。实现层必须**多一个 `NOT_ASSESSED`**，否则"没查出问题"与"没检查过"无法区分——这是判定类工具最容易被攻击的假合规点。

| 状态 | 含义 | 触发条件 |
|---|---|---|
| `BLOCK` | 命中确定性禁止情形 | 至少一条 `severity=block` 的规则被判 `noncompliant` |
| `WARN` | 命中非明确禁止但需复核的表述 | 无 BLOCK，且至少一条 `severity=warn` 规则命中 |
| `OK` | 有适用规则且全部通过 | 至少一条规则被评估，且无一命中 |
| `NOT_ASSESSED` | **未评估** | 该内容**一条适用规则都没有**（品类判为"非涉医内容"，或全部规则因品类限制被 `skipped`） |

`NOT_ASSESSED` 在报告里**独立呈现**，绝不与 `OK` 合并、绝不写成 `OK`。报告顶部同时给出"本次评估覆盖的规则数 / 规则包总数"，让读者看得见覆盖面。

### 1.2 规则级判定三态（与结论状态是两个层次）

| 规则级状态 | 含义 | 边界（必须严守） |
|---|---|---|
| `compliant` | 规则适用且未命中 | — |
| `noncompliant` | 规则适用且命中 | 无条件义务缺失 → 直接 `noncompliant`（**不许记成"不适用"**） |
| `skipped` | **不适用** | **只在原文自带主体/情形限制时使用**（如《广告法》§16 只管"医疗、药品、医疗器械广告"，对保健食品广告即 `skipped`） |
| `input_required` | 本规则判定需要外部材料，本次未提供 | 运行时**必须显式索要**该材料；**绝不静默判 compliant**，也绝不猜 |

**两条反面纪律（skill 两次实录的失败模式，本项目显式禁止）**：

1. **不许把"用户没提供材料"记成 `skipped`**——那会把"没做"记成"不用做"，结论虚高。材料缺失一律 `input_required`。
2. **不许把"无法确定性判定"记成 `compliant`**——如"药品广告内容不得与批准的说明书不一致"没有说明书就判不了，只能 `input_required`。

### 1.3 兜底条款不建规则（宁缺勿造）

《广告法》§16 第（五）项与 §18 第（六）项均为"法律、行政法规规定禁止的其他内容"——**无法确定性判定**。处置：**显式不建规则**，在"未启用清单"里写明"该项为兜底条款，无可机读判定要素，不参与引擎判定"，并同步在基准 notes 里如实写"该类用例未生成"（**不假装覆盖**）。

### 1.4 适用域必须落进规则数据（防"拿不适用的条款指责用户"）

每条规则带 `applies_if.categories`（原文自带的主体限制），**不许写 `any`**：

| 规则来源 | `applies_if.categories` | 原文依据 |
|---|---|---|
| 《广告法》§16 | `["medical", "drug", "device"]` | "医疗、药品、医疗器械广告不得含有…" |
| 《广告法》§18 | `["health_food"]` | "保健食品广告不得含有…" |
| 《医疗广告管理办法》§6/§7 | `["medical"]` | "医疗广告内容仅限于…""医疗广告的表现形式不得含有…" |
| 《互联网广告管理办法》§7 | `["medical","drug","device","health_food","fsmp"]` | "发布医疗、药品、医疗器械…广告" |
| 《互联网广告管理办法》§8 | `["medical","drug","device","health_food","fsmp"]` | "变相发布医疗、药品、医疗器械、保健食品…广告" |

**基准必须含"这条规则不该命中"的反向样例**（如保健食品内容不得被 §16 判命中），否则适用域写错永远不红。

## 二、模块 1：SKILL.md 主入口 + 内容输入

### 2.1 输入

| 入参 | 必填 | 说明 |
|---|---|---|
| `--text` / `--text-file` | 二选一 | 待审查文案（多条目用 `scan` 走目录/清单） |
| `--channel` | 否 | 发布渠道（元信息，进报告，不参与判定） |
| `--subject` | 否 | 主体类型：`medical_institution` / `medical_aesthetic` / `drug_maker` / `ordinary_account`（元信息） |
| `--hint` | 否 | **语境提示**（LLM/人给的提示，如"疑似以养生知识变相发布"）。**只进报告 advisory 分节，永不改结论** |
| `--proof` | 否 | 广告审查证明是否已取得（`yes`/`no`/未提供） |

### 2.2 标准化输出（`normalize.py`）

`ContentItem`：`id`（确定性：`sha256(原文)` 前 12 位，**不用随机数/时钟**）、`text`（原文，逐字保留）、`channel`、`subject`、`hint`、`proof`。

**确定性纪律（SKILL.md 明写）**：LLM 不直接给 BLOCK/WARN 结论；结论只能由模块 3 产出；输入文案**只做本地处理，不外发**。

### 2.3 隐私红线的可核验形态

"纯本地、不上传文案"落成三层证据：

1. 引擎源码零网络导入（AST 静态门禁：`src/` 内禁 `socket`/`ssl`/`urllib`/`http`/`ftplib`/`requests`）；
2. 全项目零运行时第三方依赖（`pyproject` runtime `dependencies = []`）；
3. 报告与 CLI 无任何外发路径（无 telemetry、无遥测端点）。

## 三、模块 2：品类判定器（`categorize.py`）

### 3.1 输出

`CategoryResult`：`category` ∈ {`medical`, `drug`, `device`, `health_food`, `fsmp`, `non_medical`} + `evidence`（命中的品类关键词行 + 条款锚点）。

### 3.2 判定路径（规则表驱动，优先级固定）

1. **主体信号**：文案含医疗机构名/诊疗科目词 → `medical`；
2. **药品信号**：含药品通用名形态 + 批准文号形态 → `drug`；
3. **器械信号**：含器械名 + 注册证号形态 → `device`；
4. **保健食品信号**：含"保健食品/蓝帽子/保健功能"词 → `health_food`；
5. **特医食品信号**：含"特殊医学用途配方食品"词 → `fsmp`；
6. **变相信号**：以健康养生知识形式出现且伴随商品/服务信息 → 记 `variant_publish_suspect`（**不直接定品类**，交 §8 规则处理）；
7. 以上皆无 → `non_medical`。

**多品类并列**：不做"二选一"猜测——命中多个品类时**全部保留**（`categories` 为集合），各品类规则分别适用；报告显式列出"本文案同时构成：医疗广告 + 药品广告"。

### 3.3 确定性纪律

- 品类关键词表**只存在于冻结规则包**，源码零词面；
- 判定规则逐条挂法条原文（如"医疗广告"定义挂《医疗广告管理办法》§2 原文）；
- 未挂原文核对不得落库/生效（生成器断言 `quote` 逐字出现在官方快照中）。

## 四、模块 3：禁止情形核查（`check.py`）

### 4.1 规则 kind 分派表（结构 + 运行双层断言）

| kind | 语义 | 典型规则 | 命中时 severity |
|---|---|---|---|
| `prohibited_term` | 确定性禁止词面/模式命中 | §7（一）涉及疾病名称/药物；§16（一）功效断言 | `block` |
| `prohibited_pattern` | 结构性禁止模式 | §7（三）宣传治愈率/有效率（"X%""治愈率"共现）；§16（二） | `block` |
| `mandatory_disclosure` | **无条件义务**：必须出现某提示语 | §16 款 2 药品禁忌/不良反应标明；§18 款 2"本品不能代替药物" | 缺失 → `block` |
| `whitelist_scope` | 超出 §6 白名单的表述 | §6 未列内容（如宣传设备/技术细节） | `warn` |
| `variant_publish` | §8 变相发布（共现判定） | 养生知识 + 地址/联系方式/购物链接同现 | `block` |
| `input_required` | 判定需外部材料 | §6 末款（需执业许可证）；§7 第 2 款（需审查通过内容）；§16 款 2 前半（需批准说明书） | 不判，记待核 |

**双层断言（skill 定稿形态）**：① 结构层——分派表键集合与 `kind` 常量集合一一对应且各实现**互不相同**；② 运行层——每个 kind 真跑一遍不抛错；配变异自检（摘掉一个 kind → 必须报错）。

### 4.2 §7 八项 + §6 白名单的落地（**已按实测勘误：§6 是 8 项**）

`plan/PRECHECK-M0.md` §三 E-1 实测：《医疗广告管理办法》§6 白名单实为 **8 项**（题面写 7 项）。规则包按 **8 项**建，题面文档不改写、勘误登记在 `plan/06-交付对标.md` D8。

§7 八项逐条建规则；§6 八项逐条建白名单条目（超出白名单 → `warn`）。

### 4.3 溯源硬约束（导出前断言，不是"尽量挂上"）

每条 `Finding` 必含四要素：`clause_anchor`（条款号）、`quote`（法条原文逐字）、`evidence`（文案命中片段）、`rule_id`。**导出前断言**：

- `findings` 每条四要素非空且可解析；
- `quote` **逐字出现在该条款的官方快照切片中**（可机器核验）；
- `evidence` **逐字出现在输入文案中**（防"引用一段用户没写过的文字"）。

不满足即**报错拒绝导出**（exit 1），不留"半溯源"报告。

## 五、模块 4：分级报告（`grade.py` + `report.py`）

### 5.1 分级映射（唯一实现源 `grade.py`）

```
GRADE_MAP: severity=block & 命中 -> BLOCK
           severity=warn  & 命中 -> WARN
           有适用规则 & 无命中   -> OK
           无适用规则            -> NOT_ASSESSED
```

映射表由规则包 `severity` 字段驱动，**版本化冻结**；报告层只渲染，不重算。

### 5.2 双轨产物（单一渲染源）

- **人读**：Markdown（结论 + 分级清单 + 条款锚点 + 法条原文 + 免责声明）；
- **机读**：JSON（同一章节结构函数 `report_sections()` 产出，两个渲染器各读它——"两格式内容一致"是**结构性质**，不是人工比对）。

**机读产物逐字节可复现**：`serialize.py` 单点写盘，参数冻结（见 K5）；同输入双跑 sha256 一致，配守门测试。

### 5.3 报告必备章节（缺一即断言失败）

1. 输入事实（原文、渠道、主体、ID）；
2. **本次评估覆盖**（适用规则数 / 规则包总数 / 未启用清单）；
3. 分级结论（BLOCK/WARN/OK/NOT_ASSESSED 四态分列，**不合并**）；
4. 逐条命中明细（四要素）；
5. **待补材料清单**（`input_required` 项：需用户提供什么、为什么判不了）；
6. advisory（hint 提示，独立分区，声明"不参与分级"）；
7. **免责声明**（辅助自查，不构成法律意见，不替代官方审查）；
8. **规则来源块**（每条规则的法规名 + 条款号 + 官方 URL + 基准日）——让读者不开仓库也能核证。

### 5.4 免责声明与红线

报告强制附免责声明（题面 §六.1）；不做药品推荐、不生成推广内容（题面 §六.2）；报告**不引用真实机构违规案例**（D4）。

## 六、模块 5：真值基准（`benchmark/` + `tools/gen_cases.py`）

### 6.1 真值库三件齐备（skill 定稿，最隐蔽的"名义存在、实际无人读"）

1. **入库件**：`src/medreview/fixtures/cases.json`（`git ls-files` 可查）；
2. **位级守门**：`gen_cases.py --check` 输出 `FROZEN_TRUTH_OK`（再生成逐字节一致）；
3. **真有调用方**：`bench` 子命令**先过冻结件**（`check_frozen_ledger()` 再 `load_ground_truth()`），用户敲的那条命令真读它。

**真值库只存输入与期望**：`id` / `form` / `input` / `expect_keys`（键名自带结论，如 `"grade:BLOCK"` / `"hit:MAM-7-3"`，取值恒为哑值）。**出现 `observed` 一类字段即红**——观测必须由观测器在运行时实算（把内联输入真喂引擎），否则基准退化成"比对两份预先算好的答案"。

### 6.2 四类套件（一条命令跑全，退出码 0/1/2）

| 套件 | 内容 | 驱动方式 |
|---|---|---|
| B1 品类判定 | 合成样例 → 品类判定精确匹配 | 样本驱动 |
| B2 禁止情形核查 | 逐条禁止情形的检出/漏报/误报 | 样本驱动 |
| B3 适用域反向 | **"这条规则不该命中"的样例**（保健食品不被 §16 判命中） | 样本驱动 |
| B4 规则驱动边界 | 不读真值库，从规则表推导：**每条规则至少有一个正例命中形态 + 一个阴性形态** | 规则驱动 |

**样本矩阵必须含"卡阈值边界"类**（`threshold_exact` 验 `≥` 语义、`near_miss` 验"不到不命中"）——如"有效率 100%"（恰命中）与"有效率达到 99%"（边界）。

### 6.3 覆盖声明双登记

manifest 逐形态登记"规则包条目总数 / 真值库采样数 / 采样清单"，并显式声明"**抽样覆盖、非穷举**"——防"各有件"被读成"全穷举"。

### 6.4 可证伪探活（每套件各一条，打到端到端入口）

给每套件注入一个缺陷（坏锚点 / 期望篡改 / 适用域写反 / 边界语义改 `>`），断言 `run_benchmarks` **真返回非 0** 且文本同步声明未达标。探活前提：**期望必须有独立来源**（锚定冻结真值库，不与引擎同源）。

### 6.5 未启用不冒充通过

某类用例未生成（如兜底条款）→ `not_enabled=true` + notes 写明"该类用例未生成" + **exit 1**；与"跑了没过"同码不同义，文本可区分。

## 七、退出码契约（锁进测试，K2）

| 码 | 语义 |
|---|---|
| 0 | 完成且未命中（`OK` / `NOT_ASSESSED`） |
| 1 | 检出命中（`BLOCK` / `WARN`）——**这是"查出了问题"的既定语义，非故障** |
| 2 | 输入/用法错误（缺文件、坏格式、未知子命令、`--only` 未知名） |
| 3 | 规则包不可用（缺锚点、锚点解析不到、manifest 缺失、status 门控拦截） |

**注意**：`check` 对命中内容返回 1 是**设计语义**，不是"跑挂了"（README 与 clean-env 验证留档须按此记"✅ 符合声明语义"）。

## 八、失败路径（必须全部有测试）

| 场景 | 期望 |
|---|---|
| 缺 `--text`/`--text-file` | exit 2 |
| 文案为空/仅空白 | exit 2 |
| 规则包文件缺失 | exit 3 |
| 规则锚点解析不到（quote 不在快照中） | 该规则**拒绝加载**，进未启用清单，exit 3（若零规则生效） |
| manifest 缺失（门槛） | exit 2（配置错误，**不回落代码默认值**） |
| 真值库与生成器不一致 | exit 1 + 逐条列出缺失/多余/内容不符的用例 id |
| 输出目录不可写 | exit 2 |
