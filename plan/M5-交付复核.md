## 二、本棒的关键实测发现（写清，避免下一棒重复踩）

1. **`scan` 的人读分支只渲染第一件（真缺陷）**：原实现 `report_mod.render_markdown(results[0]["report"])`
   ——多件时第 2 件起**静默丢失**，"批量跑过了"名不副实（用户看不到它们）。修：
   `render_markdown_batch(entries, summary)` 逐件渲染；回归门 `test_scan_markdown_renders_every_item`。
2. **`scan` 读入阶段没有失败隔离（真缺陷）**：原实现直接 `normalize.read_text_file(path)`，
   一个坏编码文件**抛错终止整批**，CLI 报 exit 2 且**不产出任何报告**——与 README/SKILL
   宣称的"失败件单列，不中断整批"直接矛盾（"失败隔离"此前只覆盖判定阶段，不覆盖读入阶段）。
   修：读入阶段逐件 try/except，失败件原地登记；**只有"一个 .txt 都没有"才算无输入源**。
3. **批量机读与单件机读结构不同形（真缺陷）**：批量原用 `rep.to_dict()`（**无** `sections`/`disclaimer`），
   单件用 `render_json` → "两格式共用同一渲染源"在**批量面不成立**。修：批量逐件也走 `render_json`。
4. **SKILL.md 人读字段表漏 `notes`（K15 的"三处"其实只守了一处）**：契约块有 `notes`、
   代码常量有 `notes`、字段表**没有** → K15 号称三方对齐，实际只有契约块与代码两处有门。
   修：字段表补 `notes` + 新增 `test_skill_field_table_matches_code_fields`（双向）。
5. **章节声明必须与渲染器同源**：SKILL.md 声明 8 节 id 若与 `report_sections()` 的 id/序
   各写一份，就是第二份真相。门禁直接拿实算章节列表逐 id 对（含**序**）。
6. **"报告层零判定"的第三条门不能按裸数字判（重要勘误）**：实测 `report.py` 有结构性常量
   `0`/`3`/`12`（切片宽度、默认值），而规则包实算出的政策号集合含 `1–8` ——**裸数字判必误红**。
   定案判据：**条款号引用形态**（`§`+数字 / `第`+数字）与**百分比阈值形态**。这条把
   "内联政策数值"落成可机读形态，同时不误伤结构性常量（阴性对照坐实）。
7. **"报告层无算术"必须豁免两类字符串运算**：实测 `report.py` 的 `%` **全是模板格式化**
   （`"…%s…" % values`）、`+` 是**字符串拼接**（`…rstrip("\n") + "\n"`）。不豁免则门过宽、
   一开就红（等于没门）。门禁只放行"字符串常量参与的 `%`/`+`"，其余算术一律报红（阳性对照坐实）。
8. **阈值形态的 `%` 会与模板占位符碰撞**：实测模式 `\d+\s*%` 把 `"sha256 %s"` 里的
   `256 %` 判成阈值 → 误红。修：`%(?![sdfr%])`（排除 `%s`/`%d` 等占位符）。
9. **`report.py` 原挂着一根无用引擎线**：`from . import constants` 全文件未被使用。
   删掉后"报告层不 import 引擎模块"从"大概没有"变成**可静态核验为零**（S8 的门因此才有意义）。
10. **章节正文唯一源的重构会丢格式要件（实测踩到）**：抽出 `_section_lines` 时把覆盖表后的
    空行一起省掉了——Markdown 会把「未启用清单：（空）」**吸进上一条列表项**（列表项与后续
    段落必须空行分隔），报告排版静默走形。处置：恢复空行 + 锁回归门（`test_markdown_coverage_rows_separated_...`）
    + 变异 G11。**教训：渲染重构必须做"逐字节等价"核验，别信"看着一样"**。
11. **红线声明也要有门**："不做药品推荐"（题面 §六.2）此前只在文档里写着，改动无人看着。
    处置：对外文档（`README.md` + `SKILL.md`）各出一条声明门 + 变异 G12。
12. **新增 AST 门禁必须配双面对照**：只有阳性对照（注缺陷→报红）会漏掉"门过宽"（把结构性
    常量/模板渲染判成违规）。故三条门禁各配**阴性对照**（合法写法必须仍绿），
    否则"修缺陷"会变成"改代码去迎合门"。

## 三、报告层零判定三条 AST 门禁（plan/03 §5.2、D12）

| # | 门禁 | 判据（可机读形态） | 阳性对照 | 阴性对照 |
|---|---|---|---|---|
| S8 | **不 import 引擎模块** | 相对/绝对导入的模块名 ∈ 引擎模块集合（`constants`/`model`/`ruleset`/`check`/`grade`/`pipeline`/…） | 注入 `from . import grade` → 命中 `['grade']` | 标准库 `re` 不报 |
| S9 | **不做算术** | AST `BinOp` 的运算符 ∈ 算术集合，**豁免**：左操作数为字符串常量的 `%`（模板）、任一侧为字符串常量的 `+`（拼接） | 注入 `total = a + b` → 命中 `[(1,'Add')]` | `'…%s…' % n` 与 `'a' + 'b'` 不报 |
| S10 | **不内联政策数值** | 正则命中 `§\d+` / `第\d+` / `\d+\s*%(?![sdfr%])`（条款号引用 / 百分比阈值形态） | 注入 `§1` 与 `1%` → 命中 `['1%','§1']` | `{1:'#', 2:'##'}` 与 `text[:12]` 不报 |

三条同时进 `medreview selftest`（S8/S9/S10，含阳性对照）与
`tests/test_m5_delivery.py`（测试面，含阴性对照与"与 selftest 同源"断言）。

## 五、批量通路演示（`scan`，当轮实测）

样例目录 `samples/`（3 件，机构名全在假机构名白名单内）：

```
samples/demo.txt         XX医疗美容门诊部（虚构）双眼皮手术，保证治愈。   → BLOCK
samples/health_food.txt  本品保健食品可有效降血糖、降血压，无任何副作用。 → BLOCK
samples/non_medical.txt  今天天气不错，适合出门散步。                     → NOT_ASSESSED
```

```
$ medreview scan --dir ./samples --format markdown --out report.md   # exit 1（查出了问题）
$ medreview scan --dir ./samples --format json     --out report.json # exit 1
$ # 机读 summary：{"total": 3, "failed": 0, "finding": true}
$ # 机读逐件 grade：BLOCK / BLOCK / NOT_ASSESSED
$ # 人读 250 行：`## 件 1/3` `## 件 2/3` `## 件 3/3`，共 24 个 `###` 章节（3 件 × 8 节）
```

**退出码**：`EXIT_FINDING(1)` = 批量中存在 BLOCK/WARN；失败件**不改**退出码
（"没判定" ≠ "判出违规"）；目录下无 `.txt` → `EXIT_INPUT(2)` 且**不产出报告**。
