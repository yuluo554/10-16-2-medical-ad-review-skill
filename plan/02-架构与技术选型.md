# 02-架构与技术选型

- **版本**：v1（2026-10-15）
- **上游**：`plan/01-题目文档.md`（需求定稿）、`plan/PRECHECK-M0.md`（数据底座实测）

## 一、交付形态决策

| 项 | 决策 | 理由 |
|---|---|---|
| 交付形态 | **Agent Skill（SKILL.md 主入口）+ 纯 CLI 确定性引擎** | 题面产出物即"Skill：SKILL.md + 确定性脚本 + references 规则包"，两者一体：SKILL.md 给宿主 agent 读，引擎给人和 agent 跑 |
| GUI / Web 面板 | **不做** | 题面未要求；无界面即无"界面层第二份判定逻辑"的风险面，也无 Qt 重件与打包分档问题 |
| 冻结 exe | **不做** | 纯 stdlib 零依赖 CLI，源码即交付；发布物 = 源码 zip（skill 的"纯 CLI 零依赖项目发布形态"） |
| 运行时第三方依赖 | **零** | 结论 100% 可复现、基准可离线跑、"纯本地不上传文案"成为**产物级可核验事实**而非声明 |
| LLM | **代码内零 LLM 调用**（见下） | 与题面"LLM 只做品类识别与语境判断、不拍脑袋"的最强落地形态 |

### LLM 参与口径（关键决策，须与题面对齐）

题面要求"LLM 只承担品类关键词识别与语境判断，不自行发明规则、不拍脑袋下结论"。本项目的落地方式：

1. **引擎（Python CLI）零网络代码、零 LLM 调用**——所有分级结论由确定性规则产出。这是可核验的（AST 静态门禁断言 `src/` 无 `socket`/`urllib`/`http`/`ssl` 导入）。
2. **LLM 的角色由宿主 agent 承担**：宿主读 `SKILL.md`，按其中的用法调 CLI；agent 的语境判断以 `--hint` 形式**显式入参**（结构化提示，如"疑似以养生知识变相发布"）。
3. **提示只进报告、永不改结论**：`hint` 命中项进报告 `advisory` 分节（独立于 BLOCK/WARN/OK 三态），**不参与任何分级计算**。有测试锁死"同一输入加不加 hint，BLOCK/WARN/OK 集合逐项相同"。

这样"LLM 只做语境判断"是真实现了，且"LLM 不产结论"从口头承诺变成机器可证伪的性质。

## 二、技术选型

| 层 | 选型 | 约束 |
|---|---|---|
| 语言/解释器 | Python，**底线 3.8**（本机 3.8.8 + 3.12 双通道） | 3.8 兼容写法：禁 `list[str]`（用 `typing.List`）、禁 `Path.write_text(newline=)`、禁 walrus 之外的新语法 |
| 依赖 | 仅 stdlib（`argparse` / `dataclasses` / `json` / `re` / `pathlib` / `hashlib` / `difflib`） | 运行期 extras 为空 |
| 测试 | `pytest`（**dev extra，仅此一个**）+ `pyyaml`（CI workflow 解析守门用） | 测试期依赖必须齐备，避免"本机碰巧装过"型假绿 |
| CLI | `argparse` 子命令 | 无 `click`/`typer` 等第三方 |
| 数据 | JSON（冻结规则包 + 冻结真值库） | 序列化参数冻结（见 §五） |
| 报告 | Markdown（人读）+ JSON（机读），**单一渲染源** | 机读产物逐字节可复现 |
| 打包/发布 | 源码 zip（`git ls-files` 收集 + `ZIP_STORED` + 固定 `date_time`） | 不引 wheel/sdist/PyPI |

## 三、分层架构

```
                ┌─────────────────────────────────────────────┐
  用户/宿主 agent │  SKILL.md（主入口：用法 + 机器可解析契约块）  │
                └───────────────────┬─────────────────────────┘
                                    │ 调 CLI
┌───────────────────────────────────▼─────────────────────────┐
│ 编排层  cli.py  ── check / scan / rules / bench / selftest   │
│  退出码契约：0 未命中 · 1 检出命中 · 2 输入/用法错误 · 3 规则包不可用 │
└───┬──────────────┬──────────────┬──────────────┬─────────────┘
    │              │              │              │
┌───▼────┐   ┌─────▼─────┐  ┌─────▼─────┐  ┌─────▼──────┐
│输入层   │   │规则层      │  │判定层      │  │报告层       │
│normalize│──▶│ruleset     │─▶│categorize  │─▶│report       │
│+model   │   │loader      │  │check       │  │(md + json)  │
│        │   │(锚点硬门)   │  │grade       │  │单一渲染源    │
└────────┘   └────────────┘  └────────────┘  └─────────────┘
                    ▲                              ▲
                    │ 只读冻结件                     │ 只消费结论
        src/medreview/references/            （渲染层零判定）
        src/medreview/fixtures/
                    ▲
                    │ 生成（tools/ 下，不入运行时）
        data/knowledge/raw/*.txt（官方快照，-text 冻结）
```

**层间纪律（三条，落成静态门禁）**

1. **规则层是唯一真相点**：任何条款号、关键词面、阈值只存在于冻结规则包；`src/` 源码零政策词面（零字面量门禁）。
2. **判定层不自己编规则**：`check.py` 只按规则包 `kind` 分派，不硬编码任何禁止情形。
3. **报告层零判定**：`report.py` 只渲染判定层给出的结论，不重算、不新增结论（判别：把报告单独发给没有引擎的人，看不出它"算"过）。

**两个"放对位置"的决策（预防 skill 记录过的真缺陷）**：

- **`benchmark/` 放在仓库顶层会被漏装**（"安装面第四面"实测坑）。本项目 `benchmark/` **只被 `tools/` 与 `tests/` 使用、不被 `src/medreview/` 运行时引用**——CLI 的 `bench` 子命令走 `src/medreview/` 内的薄转发；`benchmark/` 不入安装面，也不进打包白名单。若将来 CLI 真要引用它，必须同时改 `pyproject` 的 `package-dir` 映射并加"解析结果真存在"的守门。
- **`tools/` 一律不挂到用户 CLI 上**：发版/扫描工具是"给我自己用的"，进 `tools/`；用户 CLI 只留用户命令（`check`/`scan`/`rules`/`bench`/`selftest`）。

## 五、单一真相点清单（动了会打挂测试的口径）

| 编号 | 口径 | 唯一实现点 | 守门形态 |
|---|---|---|---|
| K1 | 条款号锚点 + 法条原文 | `src/medreview/references/`（生成物） | 锚点解析不到的规则**拒绝被加载**，进"未启用清单"显式报出 |
| K2 | 退出码语义（0/1/2/3） | `cli.py` 单一分派 | 锁进 CLI 端到端测试；`--only` 未知套件名走 2 |
| K3 | BLOCK/WARN/OK 分级映射 | `grade.py`（`GRADE_MAP` 由规则包 `severity` 驱动） | 映射表版本化冻结；报告不重算 |
| K4 | 判定三态语义（见 03） | `check.py` + `ruleset.py` | 反向样例集（"这条规则不该命中"）必红即缺陷 |
| K5 | 序列化参数（编码/排序/换行/尾换行） | `serialize.py` 的 `write_atomic` | 同输入双跑逐字节一致 |
| K6 | 基准门槛数值 | 规则包 `manifest.json`（数据非代码） | 删 manifest 后 runner 必须报配置错误（exit 2），不得回落默认值 |
| K7 | 对账语义（非 pass 集合比较） | `benchmark/cases.py` | 真值库测试与基准**共用同一函数** |
| K8 | 版本号 | 由 `references/manifest.json` 派生 | 报告与 CLI 双出口取同一派生值，代码内零版本字面量 |
| K9 | 词表/关键词面 | 冻结规则包 | 源码零词面（零字面量门禁）；测试按**下标**取词，不复制词面 |

## 六、本机环境事实与禁忌（实测，2026-10-15）

| 项 | 实测 | 处置 |
|---|---|---|
| 解释器通道 | `py -0p`：3.8.8-64 + 3.12-64 两条 | 每里程碑**双解释器全量复跑**；3.8 是底线门 |
| 3.8 语法 | 只能写 3.8 语法 | 一次性脚本/生成器同样受限 |
| pip 代理污染 | 系统代理指向错误地址 | 需装包时 `NO_PROXY="*" no_proxy="*"` + 清华镜像 |
| pyc 偶发损坏 | 有先例 | 全程 `PYTHONDONTWRITEBYTECODE=1`；怪错先清 `__pycache__` 再重试 |
| 控制台编码 | 中文控制台 cp936 | 命令用 `py -X utf8`；**但代码内入口仍要 `_ensure_utf8_stdio()`**（CI 是 cp1252，本机习惯掩盖缺口） |
| 子进程解码 | `text=True` 走 locale | 凡 `subprocess` 一律显式 `encoding="utf-8", errors="replace"` |
| 临时文件 | Git Bash `/tmp` 与 Windows Python 不通 | 临时目录一律用工作区相对路径或 `tempfile`，验证产物**不放仓库树内** |
| pytest 坑 | `capsys.readouterr()` 只能消费一次；StringIO 桩断言须 `.getvalue()` | 写测试时直接按此形态 |
