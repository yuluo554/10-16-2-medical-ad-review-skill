## 二、本棒的关键实测发现（写清，避免下一棒重复踩）

1. **plan/03 §6.2 的"卡阈值边界"示例（「有效率 100%」恰命中 / 「有效率达到 99%」边界）
   在本引擎上不成立**：本引擎的规则是**词面/模式匹配**（`match.any_of` 等），
   **没有数值比较器**、没有 `≥` 语义。实测：`有效率100%` 与 `有效率99%` **同样命中**
   `MAM-7-3`（词面「有效率」），因为判据是"文案里出现了「有效率」这个词"，
   与数字无关。**结论**：边界轴必须建在**真实存在的判定线**上——本引擎的判定线有三类：
   ① literal 词形（`AL-16-1` 的「100%有效」）；② 排除语境（中性/临床词形）；
   ③ 否定辖域（同极性否定形态）。M4 按这三类各建**成对**用例（见 §三）。

2. **探活必须打到端到端入口 `run_benchmarks`**：只断言 `_run_suite` 返回未通过
   证明不了"用户敲的那条 `medreview bench` 真把缺陷跑出来了"——M3 遗留的 B4 探活
   正是打在 `_run_suite` 上（绕过冻结件加载与汇总），属弱探活。M4 四条探活
   全部经临时真值库 + `run_benchmarks`。

3. **探活必须自证"缺陷真打中了目标套件"**：若篡改被**冻结台账门**拦下
   （在套件比对之前），那证明的是台账门在起作用，不是套件判据在起作用。
   故探针必须**重算摘要 + 同步台账**（`_tamper` 函数），让失败只能来自套件比对；
   `_assert_probe_caught` 再断言"真值来源 = frozen 且目标套件在 not_met"。

4. **"改一条输入"未必构成有效探针**：M4 实测——给某用例输入追加「（改）」后
   **判据不变**（该用例的期望对尾部追加不敏感），探针空转。有效探针必须
   **真改出结论差异**（如把"断言品类"的用例输入换成非涉医内容）。

5. **生成器静默失败 = 变异空转**：M4 实测——变异注入时若把生成器代码写坏
   （如 `[]  # MUTANT` 吞掉尾逗号），`gen_ruleset.py` **抛错退出**但产物未变；
   驱动若把 stderr 丢进 `DEVNULL`，就会看到"门没红"而误判成假门。
   **纪律**：变异驱动重生成后必须**断言生成器返回 0**（本棒已加）。

6. **变异驱动的"还原"必须是干净基线**：M4 实测——一次异常退出把 `cases.py`
   留在变异态，下一轮备份就备份了脏状态，"还原"反而把变异固化。
   **纪律**：注入前必须 `assert_baseline_clean()`（断言所有替换目标串都在、
   且无残留 `MUTANT` 标记）。

7. **`data/README.md` 计数表已被漂移门禁看住（K26）**：M4 改用例（58 → 66）后
   该门立刻红——必须同步该表。M4 新增一行"真值形态分布"，并**同源门禁**
   `test_data_readme_form_counts_match`（形态分布也纳入漂移守护）。

8. **覆盖声明双登记不能互相牵制（生成环）**：若把真值库采样数写进 manifest，
   则 manifest 随用例增删而变 → `gen_ruleset --check` 与 `gen_cases --check`
   互相依赖（改一处的 `--check` 必红）。**处置**：数值留在各自的单一实现源
   （规则包侧记"条目总数 + 形态轴"；真值库侧记"逐形态采样数 + 采样清单"），
   跨件一致性交给**门禁测试**（`test_coverage_declaration_is_double_registered`）。

9. **B4 覆盖的"唯一覆盖"用例是探活的构造前提**：M4 实算得 4 条规则
   （`IAM-7-2` / `AL-16-D3` / `AL-16-D4` / `AL-16-D5`）各只有 1 个 B4 用例覆盖。
   探活删除其中一条即构造"覆盖缺口"。**下一棒**：若新增规则，B4 分母变化，
   本探活会自动重算（不硬编码规则 id），但须确保仍存在"唯一覆盖"的规则。

## 三、卡阈值边界用例逐条（当轮实测）

**本引擎的判定线**（无数值比较器）：literal 词形 / 排除语境 / 否定辖域。
每类建**成对**用例：`threshold_exact`（恰在线上 → 命中）vs `near_miss`（不到线 → 不命中）。

| 判定线 | threshold_exact（恰命中） | near_miss（不到不命中） | 实测 |
|---|---|---|---|
| ① literal 词形（`AL-16-1` 的「100%有效」） | **B2-015**「本品100%有效」→ BLOCK / hit:AL-16-1 | **B2-016**「本品99%有效」→ WARN / 无 hit<br>**B2-017**「本品百分百有效」→ WARN / 无 hit | ✅ 两侧均如预期 |
| ② 排除语境（中性/临床词形包住裸词） | **B2-018**「保证治愈」→ BLOCK / hit:MAM-7-2 + AL-16-1 | **B2-019**「开展根治性手术」→ WARN / 无 hit<br>**B2-020**「治愈系装修风格」→ WARN / 无 hit | ✅ 排除语境生效 |
| ③ 否定辖域（同极性否定形态） | **B2-021**「可根治」→ BLOCK / hit:MAM-7-2 | **B2-022**「不能保证治愈」→ WARN / 无 hit | ✅ 否定抑制生效 |

> **纪律**：边界用例必须**成对**且**两侧都被真值库断言**（只有一侧 = 边界轴退化，
> 判据分不清"词面判定线"与"任何数字都命中"）。门禁：`test_boundary_forms_present_and_paired`
> + `test_threshold_exact_cases_assert_a_hit` + `test_near_miss_cases_forbid_hit_and_block`
> + `test_boundary_cases_actually_pass_the_engine`（逐条真跑）。
