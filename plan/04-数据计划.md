## 二、A1 官方快照（M1 核心交付）

### 2.1 抓取与入仓

- 三源（`plan/PRECHECK-M0.md` §一 S1–S3）现场抓取 HTML → 剥标签 → 正文文本快照；
- 快照入仓 `data/knowledge/raw/`，**`.gitattributes` 标 `-text`**（防克隆时 EOL 归一化改字节、sha256 失配）；
- 快照**无时间戳**、`write_bytes` 落盘（`newline='\n'` 或直接 bytes），配"再生成位级一致"守门。

### 2.2 台账（生成物，非手编）

`data/ledger.csv`：`asset_id, path, sha256, source_url, captured_date, notes`。由 `tools/gen_ruleset.py --update-ledger` 实算重建（**手改台账 = 与实算漂移**，守门测试当场检出）。

**"数据日 vs 抓取日"纪律**：本项目的 `captured_date` 指**抓取日**（2026-10-15），法规无"数据日"概念；但字段名必须写 `captured_date` 而非含混的 `date`，避免后续误当"数据日"用。

### 2.3 逐字核验（硬门）

`clauses.json` 每个条文块的 `text` 必须**逐字出现在对应快照中**（生成器断言）；不通过即生成失败。这是"脚本转写 + 原文逐字包含断言、禁止手抄"的落地。

## 三、A2 条文块切分（解析层）

### 3.1 条号只认"定义位"（防条号劫持）

正文里交叉引用别条是常态（本项目实测：《医疗广告管理办法》罚则正文引用其他条号；《广告法》§16 引"法律、行政法规"）。切分器**只认行首条号**（官方文本条号一律起于行首），交叉引用不参与切分。

**实测验证**（`plan/PRECHECK-M0.md` §一）：按行首条号切分后三源条号序列**连续无重复**（74 / 32 / 23）——证明切分口径在本项目数据上成立。

### 3.2 形态支持矩阵（按官方实际形态枚举）

| 形态 | 本数据是否出现 | 支持 |
|---|---|---|
| `第X条` | ✅（全部三源） | ✅ |
| `第X条之一` | 未出现（实测序列无重复条号） | ✅ 实现支持，数据未覆盖 |
| `（一）` 中文序号（款项/项） | ✅（§16/§18/§6/§7 均用） | ✅ |
| 款（条内分段） | ✅（§16/§18/§7 多款） | ✅ |

**留档**：生成器输出形态支持矩阵，显式写明"哪些形态已支持、哪些数据未覆盖"。

### 3.3 断行交叉引用的回读校验

定位结果必须**回读原文逐字校验**（不只信 `located` 布尔）——本项目数据实测未见断行交叉引用，但校验一律保留（防未来快照改版）。

## 四、A3 规则包（版本化冻结 + status 门控）

### 4.1 条目结构

```json
{
  "id": "MAM-7-3",
  "source": "medical_ad_measures",
  "clause": "7",
  "item": "3",
  "anchor": "《医疗广告管理办法》§7 第（三）项",
  "quote": "宣传治愈率、有效率等诊疗效果的",
  "quote_status": "verified",
  "kind": "prohibited_pattern",
  "severity": "block",
  "applies_if": {"categories": ["medical"]},
  "pattern_id": "cure_rate_claim",
  "notes": ""
}
```

### 4.2 双重门控（数值门 / 条款号门分开）

- `quote_status` = **法条原文核对状态**（`verified` / `pending`）；
- `anchor_status` = **条款号核对状态**（`verified` / `pending`）。

**只有 `quote_status=verified` 且 `anchor_status=verified` 的规则才进引擎**（锚点硬门）；两个状态都在"未启用清单"里显式可见。

### 4.3 status 作用域门控（分计算路径）

规则包承载多用途参数时用"整包全 verified"当唯一门会误阻断。本项目作用域：

| 作用域 | 校验范围 | 用途 |
|---|---|---|
| `check` | 判定类规则的 `quote_status` + `anchor_status` | `check`/`scan` 通路 |
| `bench` | 基准门槛（manifest）+ 全部判定类规则 | `bench` 通路 |
| `rules` | 仅展示，不做门控 | `rules` 列表通路（可预览 pending 条） |

**第三态 `input_required`**：本不由规则包承载的外部输入（执业许可证、审查通过内容、批准说明书）标它，**不阻断门控**但运行时必索（见 `plan/03` §1.2）。

### 4.4 零政策字面量门禁

- 把规则包全部关键词面/条款号形态/年度数字收编为禁用 token（**运行时从规则包实算**，源码零词面）；
- 扫描面：`src/` 全部源码（**含 docstring/注释**）、`benchmark/`、`tests/`、`SKILL.md` 的契约块；
- **豁免口径写死**：< 100 的小整数（长度/精度约定）、`0/1/-1`、退出码数字 0–3、`hashlib` 十六进制；
- 配 `--selftest` 阳性对照（注入一个词面 → 门禁必须报红）。

### 4.5 版本号从数据派生

`manifest.json` 的 `ruleset_version` + 条目计数由生成器实算；`src/medreview/__init__.py` 的版本从 manifest 读，**代码内零版本字面量**。

## 五、A7 合成数据纪律（题面 §四硬要求）

### 5.1 假机构名白名单

- 所有样例机构名用虚构名，格式 `XX医疗美容门诊部（虚构）` / `XX市第X医院（虚构）`；
- `data/fake_org_whitelist.txt` 维护白名单；
- **基准断言脚本校验样例中的机构名必须在白名单内**（扫到白名单外的机构名形态即红）。

### 5.2 不引用真实机构违规案例

样例文案不影射、不复述任何真实机构的广告或处罚案例（D4）。

### 5.3 真值标签挂法条

每个样例的 `expect_keys` 逐条注明支撑条款（如 `hit:MAM-7-3`）；`gen_cases.py` 落库前跑**生成守卫**——期望值与**独立朴素 oracle** 重算逐条一致才许写盘。

**观测器独立性**：真值库只存输入与期望；观测由观测器把内联输入**真喂引擎**后取出。判别 = "把主实现的判定逻辑注释掉，生成器还能算出期望吗？"不能就是同源，基准会跟着实现一起错。

### 5.4 确定性生成

- 禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟；
- 自研确定性 RNG（splitmix64 变体，整数运算跨版本一致）；
- 落盘无时间戳，两次运行逐字节一致。

## 六、A8 基准门槛随数据下发

`manifest.json` 的 `benchmark_thresholds`：

```json
{"b1_min_accuracy": 1.0, "b2_false_block_max": 0, "b3_reverse_pass_min": 1.0, "b4_coverage_min": 1.0}
```

基准层**只读**；缺失即报配置错误（exit 2），**不得回落代码默认值**（K6）。门槛数值**不在代码/文档/测试里出现第二份**（守门测试锁"runner 读 manifest 而非常量"）。

## 七、数据获取的降级与红线

1. **nmpa.gov.cn 返回 412 WAF**（`data/README.md` §二.1）——不依赖该站直连；
2. **flk.npc.gov.cn 正文 JS 渲染**（§二.2）——以 samr.gov.cn 为准；
3. **《医疗美容广告执法指南》未定位**（§二.3，S4）——不进入首期，**未挂原文核对不得落库/生效**；
4. **查证失败降级继续**：两个渠道都查不到 → 落"待核对" + 记录已查渠道，不停摆、不反复重试同一渠道；
5. **引用纪律**：涉及法规的结论必须挂出处（法规名 + 条款号 + URL + 基准日）；无出处的数值不得用确定语气。
