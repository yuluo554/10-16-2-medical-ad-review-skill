## 一、复核方法与判据

**判据**：对每个条款构造**正例**（真违规形态，必须命中）与**负例**（中性/合规
形态，不得命中）两侧探针，喂进引擎看结论。

- **误报**（把合规文案报成违法）优先级**高于**漏报——用户按误报提示改文案
  反而改错；本领域的法条又**强制要求**写免责语，而免责语恰含被禁词面，
  误报风险天然偏高。
- **漏报**（该抓的没抓）在"规则抓不到自己的目标形态"时最严重——规则看着存在，
  实际对目标内容零命中（静默失效）。
- 每条修正都配**阳性对照**（该命中仍要命中），否则只是把规则改哑。
- 词面一律**运行时从冻结规则包实算**，不在测试/文档里复制第二份词表。

## 二、实测缺陷与修正（六类）

### 缺陷 1：比较类规则缺"被比较对象"要件（§16（三）／§18（四））

原文的构成要件是「与**其他药品、医疗器械**的功效和安全性或者**其他医疗机构**
**比较**」——**比较**是动词，被比较对象是构成要件，不是可选修饰。原实现是
裸比较标记词表，实测三类误报：

| 探针 | 修正前 | 修正后 | 性质 |
|---|---|---|---|
| 「与其他机构开展**学术交流**」 | BLOCK（裸`其他机构`） | WARN | 中性搭配被判比较 |
| 「与其他机构**合作共建**」 | BLOCK | WARN | 同上 |
| 「**领先于**行业标准」 | BLOCK | WARN | 比较对象是"标准"，不在原文点名范围 |
| 「**最先进**」（无任何对象） | BLOCK | WARN | 无比较对象的孤立断言 |
| 「本品保健食品**口感好于普通食品**」（§18（四）） | BLOCK | WARN | 对象是普通食品，非"药品/其他保健食品" |

**修正**：改**同段共现**（`segment_groups`）——比较标记 × **同类指向对象**
（其他药品/器械/医疗机构/医院/诊所/保健食品/品牌/厂家/同类产品/竞争对手/同行），
且两者须落在**同一句读段**内。

**为什么必须"同段"而不只是"共现"**：全局共现会把**分属两句**的词面凑成一次
命中（如「本店技术更好。另售其他商品。」被读成"更好 + 其他商品"的比较）。
原文要求的是"**同一句陈述里的比较**"，故共现必须约束到句读段内。

**新增原语**：`phrase.cooccur_in_segment(text, groups, contexts)`（唯一实现源），
`check.match_rule` 支持 `segment_groups` 字段。句读分隔符与否定辖域**共用**
`constants.SEGMENT_DELIMITERS`（一个定义，不是两份）。

阳性对照：真比较语义（优于其他医疗器械／超过其他医疗机构／与药品比较）仍全部命中。

### 缺陷 2：裸词与临床/营养学术语碰撞（中性词形误报）

| 规则 | 原词表（问题项） | 实测误报 | 修正 |
|---|---|---|---|
| `AL-16-1` / `MAM-7-2` | 裸 `根治` | 「开展肿瘤**根治性**手术」「可实施**根治术**」「**根治率**较高」被判 BLOCK | 补排除语境 `根治性`/`根治术`/`根治率`（与 M1 的 `治愈系` 同族） |
| `AL-18-3` | 裸 `必需` | 「含人体**必需**氨基酸」「富含**必需**脂肪酸/营养素」「生活**必需**品」被判 BLOCK | 补排除语境 `必需氨基酸`/`必需脂肪酸`/`必需营养素`/`必需微量元素`/`必需矿物质`/`必需品` |
| `AL-18-4` | 裸 `好于` | 「口感**好于**普通食品」被判 BLOCK | 与缺陷 1 同源修正（对象要件）+ 补排除语境 `药品级` |

**通用结论**：本领域的 interpretive 词表**不得含裸单字/裸短词**（M1 已立门禁），
且**裸短词与专业术语的碰撞需用排除语境处置**——排除语境逐条必须**包住本类某个
正向词**（防装饰性排除，M2 的 K23 门禁同源）。

### 缺陷 3：并列宾语被当成"任一即可"（§16 款 2 药品义务，**漏报**）

原文是「并应当显著标明**禁忌、不良反应**」——**并列宾语，两项都要标明**。
原实现的 `require_all_of` 把两项放进**同一组**，而组内语义是"任一即可"
（`_any_of`），于是「只标禁忌、未标不良反应」被判 **compliant**——**漏报**。

**修正**：拆成两组（`[["禁忌"], ["不良反应"]]`），缺任一组即 noncompliant。

阳性对照：两项都标明 → compliant（不误报）；只标其一 → noncompliant。

> **连带发现（同类风险面）**：这是"并列义务"的通用形态——凡原文用「、」并列
> 两个义务宾语，都必须拆成两组。当前其余义务条均为单一提示语，无此形态；
> **下一棒若新增并列义务条，必须逐项拆组**（已写进门禁注释）。

### 缺陷 4：§7（一）规则抓不到自己的目标形态（**召回缺口**）

原文第（一）项枚举是「涉及医疗技术、诊疗方法、**疾病名称**、药物」——
「疾病名称」是**类别词**，字面几乎不出现在广告里。只匹配这四个字面时，
规则对本项的**目标内容**（真实疾病名）零命中：

| 探针 | 修正前 | 修正后 |
|---|---|---|
| 「专治**糖尿病、高血压**」 | WARN（零命中） | BLOCK（`MAM-7-1B`） |
| 「治疗**近视**手术」 | WARN | BLOCK（`MAM-7-1B`） |

**修正**：另立一条 **interpretive** 规则 `MAM-7-1B` 承载**具体疾病名**
（与 §18（二）疾病名族同源），与 literal 条 `MAM-7-1` **分开挂 `terms_basis`**
——不把解释层混进原文层（分级口径不被稀释）。

**同源判据**：门禁断言两条规则的疾病名词表**交集非空**（防两处各写一份解释层）。

### 缺陷 5：同极性否定表述结果不一致（**语言层**不一致）

实测：同一极性（斥否）的两句结论不同——「严禁贬低他人」被抑制，
而「坚决抵制淫秽低俗内容」被判**命中**（"抵制低俗"是合规表态，被判违法 = 误报）。

**修正**：`constants.NEGATION_MARKERS` 补入斥否类动词 `抵制`（与 `严禁` 并列）。
判据是**结构性**的（"否定谓语指向的对象本身即不该有"），换任何中文法规都成立。

**门禁**：`test_polarity_marker_consistency` 断言同极性表述结果**必须一致**，
且斥否类表述**不得**被判命中。

### 缺陷 6：§6 白名单外判定面只覆盖一个方向（**判定面缺口**）

§6 是**穷举式**白名单（原文「医疗广告内容**仅限于**以下项目」），故"超出白名单"
有**两个**方向：

| 方向 | 内容 | 修正前 | 修正后 |
|---|---|---|---|
| ① 医疗宣称类 | 疗效/无痛/专家坐诊/设备先进/技术领先/成功率 | 覆盖 | 保留 |
| ② **商业促销与服务类** | 「本月**八折优惠**」「**服务态度**好，**环境优雅**，**停车方便**」 | **零命中** | WARN（补入词表） |

**修正**：`MAM-6-W` 词表补入方向②（优惠/折扣/促销/体验价/免费体验/限时/
服务态度/环境优雅/停车方便/包间）。仍是 **warn 非 block**（白名单外是待复核，
不是明确禁止）。

**门禁**：两个方向各一条门禁（用词表实算构造探针，本文件零词面）；
并断言**白名单项内**内容（8 项本身）**不得**被判超出白名单。

会把合规内容判成违规。落地为「汇总式 `MAM-6-W` + 结构化登记 `whitelist_items`」。

### 3.5 互联网广告管理办法 §7/§8

| 条/款 | 规则 | 复核结论 |
|---|---|---|
| §7 款 1：未经审查不得发布 | `IAM-7-1` | **三态复核通过**：`no`→noncompliant（BLOCK）／未提供→input_required／`yes`→compliant |
| §7 款 2：按审查通过内容发布 | `IAM-7-2` | **情形门控复核通过**：`scenario=published` 才适用；发布前自查判 skipped |
| §8 款 1：知识形态变相发布 | `IAM-8-1` | 保留（共现：知识形态 × 商品/服务信息） |
| §8 款 2：知识形态 + 地址/联系方式/购物链接 | `IAM-8-2` | 保留 |

**三态语义要点**：`proof=no` 是**无条件义务缺失** → noncompliant（**绝不记成
"不适用"**，那会把"没做"记成"不用做"）；未提供 → input_required（**绝不静默判
compliant**）。门禁对三态**逐态**断言。

**情形门控要点**：`applies_if.scenario` 来自**原文自带的前提**（"已经审查通过"），
不是代码里的情形判断——门禁断言 `rule_applies` 读的是规则数据。

## 四、Finding 四要素**导出前常驻断言**（M3 头号交付物）

plan/03 §4.3 要求"不满足即报错拒绝导出（exit 1），不留半溯源报告"。M3 落地为
`pipeline.assert_findings_traceable`，**常驻在唯一导出点 `run_check`**：

| 要素 | 判据（不是"字段非空"） |
|---|---|
| `rule_id` | 非空且**存在于生效规则包**（引擎装配集合） |
| `clause_anchor` | 非空且**可解析**：含 `§<条款号>` 形态，且与规则的 `source/clause` 一致 |
| `quote` | **逐字出现在该条款的官方快照切片中**（回读 `clauses.json` 校验） |
| `evidence` | 非空；`evidence_kind == text_span` 时还须**逐字出现在输入文案**中 |

### 4.1 `evidence_kind`：把"证据的性质"做成**结构字段**

断言落地时实测暴露一个真缺陷：`prohibited_pattern` / `whitelist_scope` /
`variant_publish` 三个处理器把多个命中项 **join 成一个字符串**（`"、".join(hits)`），
而 join 出来的「保证治愈、无效退款」**不是文案里的片段**——"evidence 逐字在文案"
的断言当场报红。

- **修正**：三个处理器改为**逐命中项各出一条 Finding**（既保住可核验性，
  也让报告能逐词指认）。
- **另一类证据**：义务缺失类（`mandatory_disclosure` / `review_proof`）的证据
  描述的是"**该写而没写**"，**不可能**出现在文案里。原测试靠**字符串前缀特判**
  （`evidence.startswith("缺失应显著标明")`）绕过——脆弱：改一句措辞就绕过门禁。
- **结构化修正**：新增 `Finding.evidence_kind`（`constants.EVIDENCE_TEXT_SPAN` /
  `EVIDENCE_OBLIGATION_MISSING`），断言与测试都按**字段**分支，不靠字符串匹配。
  门禁 `test_evidence_kind_is_structural_not_string_prefix` 断言分类不依赖措辞。

### 4.2 退出码

断言失败抛 `FindingIncomplete`（`errors.py`），CLI 按 code 分档返回
**`EXIT_FINDING`（1）**——语义是"查出了问题但报告不可信"，与"检出命中"同码、
与"故障（2/3）"区分。门禁端到端断言（探针用**非涉医文本**，若断言未接线会以 0
退出 → 测试报红）。

## 六、门禁与变异验证（10 组，全部使门变红）

## 七、M3 的诚实边界（未做/做不到的，如实写）

1. **疾病名词表是解释层、非穷举**：`MAM-7-1B`/`AL-18-2` 的具体疾病名按常见形态
   采样，**不声称覆盖全部疾病名**。真实疾病名数以万计，词典化穷举超出首期范围
   （P8 决策：覆盖首期条款的**最小可判定集**）。
2. **§6 白名单外的判定面仍是采样**：商业促销/服务方向补入的是**常见形态**
   （优惠/折扣/促销/服务态度…），不是穷举——"超出白名单"本身是开放语义，
   机器只能采样 + 报 warn 交人工复核。
3. **四要素断言保证"可核验"不保证"判定正确"**：它拦的是"引文写错/证据不在文案/
   规则不存在"这类**溯源断裂**，不校验判定语义本身是否恰当（那由基准套件与
   语义门禁承担）。
4. **`evidence_kind` 是人工标注的**：由各处理器在构造 Finding 时声明。若新增
   处理器忘了标注，默认是 `text_span`（更严的一侧）——**偏严不偏松**，
   宁可误红不可放过。
5. **CI 诚实口径（同 M0/M1/M2）**：本项目当前**无远端**，`on: push` 从未被
   GitHub 执行过；M3 只能写"本地等价校验"（双解释器 + 浅克隆 + 干净 venv），
   **不写"CI 绿"**。M6 首推后据实补记真实 run id。
