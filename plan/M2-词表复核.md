## 二、实测缺陷（**写清，避免下一棒重复踩**）

### 缺陷 1：信号词表过宽 → 中性/跨行业词形被判成本品类（M2 主线）

M2 首轮探针实测（改词表前）发现 5 类**误判**，全部源于裸词面与更大词形的碰撞：

| 实测输入 | 误判结果 | 根因（裸词面） |
|---|---|---|
| 宠物医院今天打折 | `medical` | 裸「医院」 |
| 请寄挂号信至收件处 | `medical` | 裸「挂号」 |
| 健身器械专卖店开业 | `device` | 裸「器械」 |
| 办公器械维修服务 | `device` | 裸「器械」 |
| 国家药品监督管理局发布通告 | `drug` | 裸「药品」 |
| 药品监管法规汇编 | `drug` | 裸「药品」 |
| XX医美护肤品焕亮精华 | `medical` | 裸「医美」 |

**为什么这类误报比漏报更坏**：品类判错会**连带把不适用的规则套上来**——
「国家药品监督管理局发布通告」被判 `drug` 后，直接命中「药品广告未显著标明
禁忌、不良反应」判 BLOCK（实测复现）。一个监管机关名称的陈述句被报成违法广告。

**处置**：引入 `category_rules[*].exclude_contexts`（**反例结构**）——命中项落在
这些更大词形内部即不算命中。5 类误判全部消除（复测：7 例全落 `NOT_ASSESSED`）。

### 缺陷 2：反例结构可能"装饰性"（写一条无关排除词也满足"非空"）

**问题**：只断言"每类反例结构非空"是假门——写一条**与词表无关**的排除词
（如「无关装饰词形」）同样非空，却拦不住任何本类命中。

**处置**：门禁断言"**反例结构必须确实包住本类某个正向词**"
（`test_exclude_contexts_are_not_decorative`）——排除语境里不含本类任何正向词
即报红。变异验证：把 medical 的反例换成「无关装饰词形」→ 3 条门变红。

### 缺陷 3：版本号不指纹品类词表 → "版本化冻结"是假门（**K8 实质缺陷**）

**问题**：`ruleset_version` 的哈希输入原为 `{rules, excluded, whitelist}`，
**不含** `category_rules` / `variant_rules`。故只改品类词表（不改规则）时
**版本号不动**——消费者无法据版本号判断"判定数据变没变"。

**处置**：哈希输入补入两表；门禁 `test_ruleset_version_fingerprints_category_tables`
用与生成器同源的口径重算版本号并断言一致。变异验证：把版本号改回不含两表的算法
→ 该门变红。

### 缺陷 4：advisory 不进观测集合 → 提示逻辑写错永不红

**问题**：变相发布疑似（`variant_publish_suspect`）原只写进报告 advisory，
而基准的 `observed_keys` **不收集 advisory**——真值库即便断言了它也无从观测
（"该出的提示没出"永不红）。

**处置**：`observed_keys` 增加 `advisory:<kind>` 观测键；`compare_case` 增加
`advisory:` 前缀的正向子集断言；真值库 B1-011/B1-012 断言该键。
变异验证：观测器摘掉 advisory 收集 → `bench` 退 1、B1 未达标。

### 缺陷 5（**跨棒遗留，M2 实测发现**）：`data/README.md` 计数表抄了旧版本号

**问题**：`data/README.md` §一之二 写"规则包版本 `ruleset-28a4cfd991`"，
而 manifest 实为 `ruleset-f20a805f89`——文档计数与数据**漂移了整整一棒**，
此前**没有任何门看着**（文档计数靠人记得改）。

**处置**：① 按当轮实测重写该表（并补品类计数行）；② 新增门禁
`test_data_readme_counts_match_manifest`（版本号 + 生效数 + 总条目数 + 用例数）。
变异验证：把文档版本号改成 `ruleset-DEADBEEF99` → 该门变红。

## 三、品类词表复核（逐类）

| 品类 | 正向信号词数 | 反例结构数 | 反例结构（实测依据） |
|---|---|---|---|
| medical | 18 | 5 | 宠物医院 / 动物医院 / 挂号信 / 医美护肤 / 医美级 |
| drug | 13 | 4 | 药品监督管理局 / 药品监管 / 药品广告审查办法 / 药品管理法 |
| device | 11 | 6 | 健身器械 / 运动器械 / 办公器械 / 体育器械 / 厨房器械 / 器械健身 |
| health_food | 6 | 2 | 保健食品广告审查 / 保健品监管 |
| fsmp | 3 | 1 | 特殊医学用途配方食品广告审查 |

**新增正向词的选择依据**（按首期条款覆盖面，非"尽量全"——P8 宁缺勿造纪律）：

- medical：机构形态（医疗机构/医疗服务/门诊部/诊所/门诊）+ 诊疗科目形态
  （中医/口腔科/眼科/骨科/皮肤科/体检）——对应 §2 定义位「医疗机构或医疗服务」；
- drug：剂型形态（片剂/胶囊/口服液/注射液/颗粒剂/滴眼液/软膏）+ 批准文号形态
  （国药准字）——对应 §16 以"药品"为主体；
- device：器械名（血糖仪/助听器/隐形眼镜/呼吸机/假肢）+ 注册证形态（械字号/注册证）。

**未收录的词**（宁缺勿造，避免引入新误报）：通用词「说明书」「适应症」（M1 已移出，
理由同 HANDOFF-M2 §一 缺陷 6）；裸单字「药」「器」（必误报，同 K20 纪律）。

## 四、共用语面原语（`phrase.py`，M2 新增）

**决策（D20）**：品类判定**不自写一份词面匹配**，与规则核查共用唯一实现源。

- 新模块 `src/medreview/phrase.py`：`is_negated` / `excluded_context` /
  `term_is_live` / `any_of` / `all_of` / `none_of`；
- `check.py` 的六个私有原语改为 `phrase` 的**别名**（既有调用点与 M1 守门断言零改动）；
- `categorize.py` 经 `phrase.any_of` 做品类命中——品类信号词**同样受否定辖域与
  排除语境约束**（否则品类判定自成第二套口径）；
- `phrase.py` 已进零字面量扫描面（`selftest.JUDGMENT_MODULES`），且 `_ruleset_tokens`
  把品类**反例结构**也收进扫描词表（写进判定模块 docstring 同样算抄词表）。

**为什么合并而不是各写一份**：判别口诀"同一份判定，在几个地方各写了一份？"——
两份以上就是漂移源。合并后"否定辖域语义改了"，品类判定**自动同步**，不需两处改。

## 五、变相发布两款信号（§8）

| 信号 | 对应原文 | 知识形态词 | 商品/服务信息词 |
|---|---|---|---|
| `variant_health_knowledge_commerce` | §8 第 1 款「禁止以介绍健康、养生知识等形式，变相发布…」 | 养生知识/健康知识/科普/养生/调理/保养/健康科普 | 门诊部/医院/诊所/购买/预约/就诊/挂号/订购/门店 |
| `variant_health_knowledge_contact` | §8 第 2 款「…不得在同一页面或者同时出现…地址、联系方式、购物链接等内容」 | 同上 | 联系方式/购物链接/扫码/加微信/电话/微信/二维码/地址 |

**两层语义分工（重要，别混）**：

- **规则层**（`IAM-8-1` / `IAM-8-2`，`variant_publish` kind）：**确定性判定**，
  命中即 `noncompliant`（severity=block → BLOCK）；
- **品类层**（`variant_rules`）：**只出 advisory 疑似**，**不直接定品类、不改结论**
  ——它的词表更宽（含"养生""调理"等宽信号），定位是"提请人工复核"。

**为什么不合并成一层**：判定要"窄而准"（宽词表进判定必然误报），提示要"宽而全"
（窄词表会漏掉可疑形态）。两层各自承担，`test_variant_suspect_is_advisory_not_conclusion`
断言品类层疑似**不越权**改 grade/categories。

## 六、真值库扩充（B1 5 → 13）

| 用例 | 类型 | 覆盖点 |
|---|---|---|
| B1-006 | 多品类并列（三品类） | medical + drug + device 同时成立，不二选一、不降维 |
| B1-007 | 似是而非边界 | 「医美护肤品」含"医美"字面但非医疗机构 → NOT_ASSESSED |
| B1-008 | 似是而非边界 | 「健身器械」跨行业 → 不得判 device |
| B1-009 | 似是而非边界 | 「国家药品监督管理局」机关名 → 不得判 drug |
| B1-010 | 似是而非边界 | 「挂号信」中性词形含"挂号" → 不得判 medical |
| B1-011 | 变相发布疑似（无品类） | suspect 出 advisory，但**仍判 NOT_ASSESSED**（不改结论） |
| B1-012 | 变相发布疑似 + 品类成立 | 提示与规则判定**并存**（提示不替代规则） |
| B1-013 | 多品类并列（三品类） | medical + health_food + fsmp 同时成立 |

**朴素 oracle 扩展**：`advisory:` 键是**独立于结论的提示**，可与任意 grade 并存
（含 NOT_ASSESSED）——故 oracle 对它**不设 grade 约束**（这正是它的语义）。
